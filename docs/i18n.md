# Internationalization (i18n) & multilingual

The plugin has **two independent translation systems**:

1. **Admin panel** — standard WordPress gettext (`.po`/`.mo`), follows the WP locale.
2. **Consent box (frontend)** — per-template texts + a detected front-end language,
   integrates with Polylang / WPML.

Text domain: `fast-open-cmp` · Domain path: `/languages` ·
`load_plugin_textdomain()` runs on `init`.

---

## 1. Admin panel (gettext)

Source strings are **English** (`__('Save', 'fast-open-cmp')`), translations live
in `plugin/languages/`:

| File | Role |
|------|------|
| `fast-open-cmp.pot` | template — all translatable strings (English) |
| `fast-open-cmp-pl_PL.po` | Polish translation (human-editable) |
| `fast-open-cmp-pl_PL.mo` | Polish, compiled (loaded at runtime) |

WordPress loads `fast-open-cmp-{locale}.mo` for the current user/site locale. So a
**Polish** WP admin sees Polish (with diacritics); an **English** WP admin sees the
English source. Nothing else is needed — this is the standard contract that
**Loco Translate**, **WPML String Translation** and **Polylang** all build on.

### Add or update a translation

The container ships `wp-cli` at `/tmp/wp-cli.phar` (the WP image has no wp-cli).

```bash
# After changing/adding translatable strings in PHP — regenerate the template:
wp i18n make-pot . languages/fast-open-cmp.pot --slug=fast-open-cmp

# New language: copy the .pot to languages/fast-open-cmp-<locale>.po
#   (e.g. de_DE), translate the msgstr values, then compile:
wp i18n make-mo languages languages
```

(Or just use Loco Translate in wp-admin — it reads the `.pot` and writes `.po/.mo`.)

> The `.mo` is binary and `.po/.pot` are LF text — enforced by `.gitattributes`.

## 2. Consent box (frontend)

The box is **not** gettext. Its texts come from the template's stored
`config.texts`, deep-merged over hardcoded defaults. The defaults exist in **Polish
and English** (`FOCMP_API::get_hardcoded_default_texts($lang)` in
`includes/api/trait-data.php`). Publisher overrides per language live in the
`focmp_texts` option / the template config (no cross-language fallback — an EN box
never borrows PL option texts).

### Language resolution (`build_config`)

```
$lang = template.language (default 'pl')
$detected = apply_filters('focmp_detect_language', null)   // Polylang / WPML
if ($detected):
    $lang = $detected                                       // texts + GVL follow it
    if a template authored in $detected exists for the domain's company:
        switch to that template                             // per-language box texts
```

- **Without** a multilingual plugin the filter returns `null` → behaviour is
  unchanged (the template's own language).
- The response `language`, `texts` and `gvlUrl` all use the resolved `$lang`.
- The config cache key includes the detected language, so a PL config is never
  served to an EN page.

### GVL / purpose translations

Vendor-list and purposes are served per language
(`/v1/vendor-list?lang=xx`); translations are imported per language into
`cmp_purposes_iab` and `cmp_gvl_metadata` (admin → import purpose translations,
`FOCMP_Importer::import_iab_purposes_lang`).

## 3. Translation-plugin integration

| Plugin | Admin UI | Consent box |
|--------|----------|-------------|
| (none) | WP locale → `.mo` | template language |
| **Polylang** | `.mo` (+ String Translation) | `FOCMP_Polylang` → `pll_current_language()` |
| **WPML** | `.mo` (+ String Translation) | `FOCMP_WPML` → `wpml_current_language` / `ICL_LANGUAGE_CODE` |

The integration classes are loaded only when the plugin is active and register on
the `focmp_detect_language` filter (wired in `Fast_Open_CMP::init_components`).

### Custom integration / filters

```php
// Report the current front-end language (slug, e.g. 'en').
add_filter('focmp_detect_language', fn($default) => my_current_lang() ?: $default);

// Advertise available languages (array of slugs).
add_filter('focmp_available_languages', fn($langs) => ['pl', 'en', 'de']);
```

To author a per-language box, create one template per language (set its
**Language**) and assign them across the company's domains; the box switches to the
template matching the detected language, falling back to localized default texts
otherwise.
